# ACS function doc index

don't load this whole tree speculatively. See `AGENTS.md` for engine-source buckets and the

## Concepts

General ACS/BCS knowledge not tied to one function's signature — see `concepts/` in `AGENTS.md`.

- [Crash-and-bug checklist](concepts/crash-and-bug-checklist.md) — tier A. **Read this before/during
  an ACS code review.** Checklist-style index of verified, recurring crash-causing patterns (NULL
  actor pointer dereferenced with no guard, NULL `char*` from a getter fed through `strlen`,
  lookup-miss pointer dereferenced on an unresolved name, unvalidated index into an engine
  array, a raw int misused as a string-table index) plus a "looks risky but verified safe" section
  to avoid false-positive flags (divide-by-zero, invalid string handles, deep recursion, and which
  `tid=0`/no-activator calls are actually guarded). Links out to the full verified mechanism per
  finding; grows as new patterns are verified elsewhere in this tree.
- [Activation](concepts/activation.md) — tier A. `Thing_Activate`/`Thing_Deactivate` (action
  specials 130/131) unconditionally call the actor's `Activate`/`Deactivate` C++ method, but the
  **default** implementation only does anything for a living monster or ice corpse (flips
  `MF2_DORMANT`) — a no-op on any other actor unless it's one of **at least nineteen** classes
  across unrelated subsystems that override one or both (`AAmbientSound`, `ASwitchableDecoration`,
  the three Invasion spot classes, and more — see the file for the full list). **Zandronum has no
  ZScript at all**, so the wiki's entire "ZScript" section (overridable virtuals, calling
  `.Activate()` directly on a pointer) doesn't apply there — the DECORATE `Activation`
  property/`THINGSPEC_*` flags and `USESPECIAL`/`BUMPSPECIAL` actor flags are still real and
  verified, though.
- [Client-side scripting](concepts/clientside-scripting.md) — tier B. `CLIENTSIDE`/`NET` are real
  per-script flags; **client and server have entirely separate variable state** (a global changed
  server-side is invisible to a `CLIENTSIDE` script reading "the same" global); server→client
  data passes through `ACS_ExecuteAlways` args (ints work, `StrParam()` strings reportedly don't —
  unverified) — or reliably, for strings specifically, via a `NamedSendNetworkString`-driven
  `CLIENTSIDE` relay script (source-verified, the `LogTo`/`Log_To` pattern,
  broadcasts to all clients for free when `client` is omitted); client→server only via `RequestScriptPuke` into a `NET` script, which is
  console-callable by anyone (validate server-side) and unreliable (retry + idempotent-server
  pattern required).
- [Actor pointers](concepts/actor-pointers.md) — tier A. `AAPTR_*` selectors resolve through a
  single `COPY_AAPTR` priority chain (damage-event → player-specific → general → static →
  origin fallback); **`AAPTR_GET_LINETARGET` compiles but has no case in `COPY_AAPTR`, so it
  silently no-ops** instead of aiming; `AAPTR_DAMAGE_SOURCE`/`INFLICTOR`/`TARGET` are a
  Zandronum-only addition (absent from the wiki page) usable only inside a `GAMEEVENT_ACTOR_DAMAGED`
  handler; `AAPTR_PLAYER_GETFLOATYICON` has no `zcommon.bcs` constant at all and isn't reachable
  from ACS/BCS.
- [Script types](concepts/script-types.md) — tier B. The ZDoom wiki's ten-type list is wrong for
  Zandronum in both directions: `REOPEN` **does not exist** here (no enum value, no call site),
  while `EVENT` and `KILL` are real Zandronum-native types the wiki page never lists.
  Spectators never trigger `ENTER`; becoming a spectator (not just disconnecting) fires
  `DISCONNECT`; `UNLOADING` genuinely runs `ACS_Execute`-style (can block its own next run);
  per-actor `NOKILLSCRIPTS` overrides a global `forcekillscripts`.
- [EVENT scripts](concepts/event-scripts.md) — tier B. `GAMEEVENT_PLAYERJOINS` is real in the
  checked-out `3.3-alpha` source (confirmed via git ancestry against the 3.2.1 version-bump
  commit) but **postdates the 3.2.1 engine target, and isn't even exposed as a
  named BCS constant in `zcommon.bcs`** — don't use it.
  `GAMEMODE_HandleEvent` no-ops immediately in client mode, a stronger claim than the wiki's
  "event handling doesn't work in `CLIENTSIDE` scripts."
- [Units and encodings](concepts/units-and-encodings.md) — tier B. The wiki's tic-precision fix
  is **GZDoom v3.2.2-only and confirmed absent from Zandronum** (`1000/TICRATE` is still
  truncating integer division here) — 35 tics measurably take ~0.98 real seconds, not 1. The
  `speed`-argument-is-eighths-of-a-unit-per-tic pattern is the same `SPEED()` macro already
  verified for [Floor_MoveToValue](functions/floor_movetovalue.md).
- [Integer arithmetic](concepts/integer-arithmetic.md) — tier A. `int` is always signed 32-bit
  (no unsigned type, no logical-shift operator) — `>>` sign-extends (`PCD_RSHIFT` on `int32_t`)
  and `%` follows C truncated-division sign-of-dividend semantics (`PCD_MODULUS`), so any port of
  an algorithm written against unsigned 32-bit shift/modulus (PRNGs, hashes, CRCs) silently
  diverges unless corrected.
- [Constants](concepts/constants.md) — tier A. `bcc`'s `#define`/`#include` only act as full
  preprocessor directives inside an `#if`/`#ifdef`/`#ifndef` block (or after `#pragma raw
  define/include on`) — outside that they silently fall back to the weaker plain-ACS directive,
  unlike the wiki's assumption that ACS `#define` is always the preprocessor form. BCS has **no
  `const` keyword at all**; the real equivalent is `enum`, which is far richer than plain ACS
  enums (typed non-`int` bases requiring every value to be explicit, enum-typed variables with
  compile-time enforcement). The wiki's ZScript section doesn't apply — Zandronum has no ZScript.
  DECORATE's own `const`/`enum` is a separate, unrelated mechanism — see
  [`../decorate/concepts/constants.md`](../decorate/concepts/constants.md), and
  [`../shared/concepts/constants.md`](../shared/concepts/constants.md) for why the two shouldn't
  be assumed to work alike.
- [Operators](concepts/operators.md) — tier A. `&&`/`||` genuinely short-circuit (verified in
  `zt-bcc`'s codegen, which never emits the engine's non-short-circuit `PCD_ANDLOGICAL`/
  `PCD_ORLOGICAL` opcodes for them) — a right-side side effect won't run once the left operand
  decides the result. Divide-by-zero/modulus-by-zero don't crash the engine or throw a catchable
  ACS error; they print `"Divide by zero in <script>"`/`"Modulus by zero in <script>"` and
  terminate just that script instance (`SCRIPT_PleaseRemove`), firmer than the wiki's vague "will
  cause an error." `++`/`--` are correctly fixed-point-aware in BCS (`fixedVar++` adds a true
  `1.0`/65536 raw units via a dedicated `inc_fixed()` codegen path), not the raw-word `+1` a naive
  read of the `PCD_INCSCRIPTVAR` opcode would suggest.
- [String literal vs. pool equality](concepts/string-literal-vs-pool-equality.md) — tier B. `==`/
  `!=` on `str` is a raw index comparison (`PCD_EQ`/`PCD_NE`, same as `int`), never content-aware.
  Safe between two runtime-built (`StrParam`/pool-origin) strings, but **always false/true
  respectively** when one side is a compiled literal and the other pool-origin (e.g. a
  `ScriptCall`-bridged function's return value), regardless of matching text — the two live in
  permanently disjoint index ranges by construction. Use `StrCmp`/`StrIcmp` instead whenever
  either side might not be a literal from the same compiled module as the other.
- [String `+` operator variable bug](concepts/string-concat-operator-variable-bug.md) — tier B, a
  `zt-bcc` **compiler** bug (confirmed via raw opcode disassembly), not engine-specific.
  `"literal" + "literal"` correctly constant-folds to real string concatenation, but `variable +
  variable` (or any non-constant operand) silently compiles to a plain integer `ADD` on the pool
  indices instead of reaching the working `concat_str()` codegen path — no compile or runtime
  error, the result just reads back as garbage/empty. Use `StrParam`'s format-item list to build a
  string from multiple pieces instead of chained `+`.
- [Scope](concepts/scope.md) — tier A. Verified base-ACS script/map/world/global scope sizes
  (`NUM_MAPVARS`=128, `NUM_WORLDVARS`=256, `NUM_GLOBALVARS`=64) and hub/new-game reset behavior
  exactly match the wiki. **Zandronum-only divergence not on the wiki:** a fully-connected client
  does not independently clear world/global ACS vars on a level change — only the server (or a
  client without a full snapshot) does; clients rely on server replication instead
  (`g_level.cpp:579-583`, `// [AK]` comment). Also documents `bcc`-specific scoping the ZDoom page
  doesn't cover at all: `static` locals and in-script `world`/`global` declarations are ordinary
  map/world/global storage with restricted name-visibility (not a 5th scope), plus `let`/`strict
  namespace` block scoping that's tighter than the wiki's flat "script scope."
- [User-defined functions](concepts/user-functions.md) — tier A. BCS's `function` keyword is far
  richer than the ZDoom wiki's base-ACS page shows: `function`/`void` are optional for a no-arg
  void function, parameters get default arguments (even builtins like `MorphActor`) and can be
  unnamed, functions nest arbitrarily deep with real closure-style capture of enclosing locals,
  nested functions can declare `auto` return type, and `(auto()){...}()` function literals work.
  The latent-function restriction is a hard compile error covering an exact, closed set of 5
  dedicated builtins (`Delay`/`TagWait`/`PolyWait`/`ScriptWait`/`NamedScriptWait`), not just "such
  as Delay" as the wiki vaguely puts it — and the wiki's claim that runaway recursion "will
  eventually crash the game" is **false for Zandronum**: `p_acs.cpp`'s call-stack guard catches it
  first and safely removes only the offending script.
- [Libraries](concepts/libraries.md) — tier B. `#library`/`#include`/`#import`/`#linklibrary`/
  `LOADACS` mechanics. The wiki's own flagged-unverified "on a name/number conflict the one
  loaded **last** is used" is **backwards**: cross-module lookup is `StaticFindScript`'s *first*
  match over `StaticModules` in push order, and the map's own `BEHAVIOR` always occupies index 0,
  so it wins over every library. `bcc` **does not enforce** the wiki's "`#library` must be the
  first statement" (the `first_object` flag is passed in and never read anywhere in the parser)
  but does enforce a non-blank, compile-globally-unique library name. `#linklibrary` is a
  bcc-only directive the page never mentions — forces a `LOAD`-chunk entry with no compile-time
  source import. A missing `#import` source file is a hard compile error; a missing `LOAD`-chunk
  lump at runtime is only a console warning.
- [Palette translations](concepts/palette-translations.md) — tier B. `CreateTranslation` looks
  like a function call and is not one: it's a dedicated statement in both compilers' grammars
  with its own multi-clause syntax, no special/`ACSF` table entry (so it can't be `special`-
  declared or used as an expression), compiling to a *sequence* of pcodes rather than one. Covers
  slot numbering, the clause kinds and their differing operand units (the main trap), the two
  clause kinds that are GZDoom-family-only, and the bytecode shape.
- [Zandronum-vs-UZDoom ACS bytecode compatibility](concepts/zandronum-uzdoom-compat.md) — tier A.
  A Zandronum-compiled object loads fine under UZDoom and doesn't crash — it silently produces
  wrong behavior at Zandronum-only call sites instead. **ZDoom reserves ACSF/CALLFUNC index
  range 100-199 for Zandronum and implements none of it**; `zt-bcc` binds Zandronum's extensions
  there unconditionally with no engine-target flag to gate it, and UZDoom's `CallFunction`
  dispatcher's `default` case silently `return 0`s with no error message, unlike an unrecognized
  base PCD (a different, much rarer failure mode for `zt-bcc` output), which prints and
  terminates the script. Base PCD opcode numbering is otherwise identical between the two engines
  with two narrow, effectively unreachable-from-`zt-bcc` exceptions. The `CLIENTSIDE` SFLG bit
  (`0x0002`) means something on Zandronum and is explicitly documented as meaningless on UZDoom —
  a `CLIENTSIDE` script just runs as an ordinary script there, not an error but a real behavior
  change. A silent-0 return can coincidentally read as correct in singleplayer specifically
  (no console-player ambiguity, no spectators to misclassify) — don't take that as evidence a
  port is clean.
- [ACSe/ACSE compiled object format](concepts/acse-object-format.md) — tier B. Below-source-code
  level: the actual `.o`/`BEHAVIOR` binary layout, for decompiling an object with no `.acs`
  source. Header/chunk-directory trailer layout (`ACS\0` + a legacy-compat offset that itself
  points at the real `[offset][ACSe/ACSE tag]` pair, mirroring Zandronum's own
  `pretag`/`Chunks` read), the 240-value opcode escape, and the four-way per-opcode operand-width
  classification (always-byte / first-operand-only-when-compact / all-operands-when-compact /
  `CALLFUNC`'s own two-part rule) needed to disassemble compact (`ACSe`) pcode correctly — naively
  assuming "compact means everything is a byte" silently misdecodes real objects. Also covers
  `CALLFUNC` always pushing a result regardless of the callee's declared return type,
  `CASEGOTO`/`CASEGOTOSORTED` only popping on a match, `PCD_TAGSTRING` not being required before
  every string-consuming opcode (`PRINTSTRING` resolves its own operand), chunk formats for
  recovering names/data (`FUNC.size` is EXTRA locals beyond the param count, not a total; `MEXP`
  has no index field per entry so can't be reliably mapped back to a specific var/array number),
  and `PCD_CALLSTACK` (BCS-only function-pointer calls, absent from vanilla ACS) including its
  calling convention and a real-world null-check idiom that combines it with `CASEGOTO`'s
  peek-without-popping behavior.
- [Old-style `ACS\0` compiled object format](concepts/acs-old-object-format.md) — tier B. The
  Hexen-era `BEHAVIOR` layout that predates the chunked objects above, still emitted by `acc`
  when asked for Hexen-compatible pcode; a decoder written only against `ACSe` will reject or
  silently misread it. Structurally far simpler (no chunks at all), but with its own traps:
  script number and type share one field, pcode does not run to `dirofs`, string arguments carry
  no type marker, script numbers are not unique, and `delay` is one tic longer than in the newer
  format. Validated by disassembling all 939 script bodies across a 57-object corpus to exact
  instruction boundaries with zero drift.

## Families

- [Actor position-getter family](families/actor-position-getters.md) — `GetActorX`/`GetActorY`/`GetActorZ`, all tier A. Not a mandatory-sequence family, but all three share one C++ `case` block (pointer-arithmetic offset into `actor->x/y/z`); `tid=0` means activator, nonzero `tid` reads only the first matching actor — **symmetric with `SetActorPosition`, unlike the `GetActorAngle`/`SetActorAngle` asymmetry**; silent `0` conflation (bad TID/no activator/genuine zero coordinate indistinguishable); **`GetActorZ` alone adds a `GetBobOffset()` term for `MF2_FLOATBOB` actors**, causing Z-only round-trip drift through `SetActorPosition` that X/Y don't have.
- [Actor velocity-getter family](families/actor-velocity-getters.md) — `GetActorVelX`/`GetActorVelY`/`GetActorVelZ` (extension functions, indices -9/-10/-11), all tier A. Not a mandatory-sequence family, but all three are one-line cases in the same engine switch, differing only by which velocity member is read; fixed-point map-units-per-tic (sign convention verified per-axis); `tid=0` means activator, nonzero `tid` reads only the first match — **asymmetric with `SetActorVelocity`, which mutates every actor sharing the TID**; silent `0` conflation is materially worse than the angle-getter's, since `velz==0` (resting) is the majority case rather than a rare exact value; `GetActorVelZ` always reads `actor->velz` directly even for players, unlike `SetActorVelocity`'s player-bob-only X/Y write path.
- [CVar family](families/cvar.md) — `GetCVar`/`SetCVar`/`GetCVarString`/`SetCVarString`/`GetUserCVar`/`SetUserCVar`/`GetUserCVarString`/`SetUserCVarString`, all tier A. All eight are thin `is_string`-flagged wrappers around just four static helpers (`GetCVar`/`SetCVar`/`GetUserCVar`/`SetUserCVar`), so behavior verified for one form (e.g. the int form) applies to its string sibling too. **The string forms' "not found" return is not a safe empty string** — it's the raw literal `0`, which resolves as string-table index 0 of the current behavior module (whatever string the compiler put there), not `""`. Float cvars round-trip transparently through the int forms via fixed-point conversion. `GetCVar`/`SetCVar` redirect to the `User` variants for `CVAR_USERINFO` cvars (with a Zandronum-only clientside consoleplayer fallback on the `Get` side, not on `Set`). `SetCVar` respects `CVAR_NOSET`; `SetUserCVar` does **not** — an undocumented asymmetry. `SERVERINFO` cvars silently no-op for non-arbitrators but `SetCVar`/`SetUserCVar` still report success. Setting your own userinfo cvar via `SetUserCVar` also mirrors into the local cvar copy and queues client→server replication — Zandronum netcode with no ZDoom-wiki equivalent.
- [Database family](families/database.md) — `SetDBEntry`/`GetDBEntry`/`SetDBEntryString`/`GetDBEntryString`/`IncrementDBEntry`/`GetDBEntryRank`/`GetDBEntries`/`SortDBEntries`/`CountDBResults`/`GetDBResultKeyString`/`GetDBResultValueString`/`GetDBResultValue`/`FreeDBResults`/`BeginDBTransaction`/`EndDBTransaction`, all tier A. **The database defaults to `:memory:`** (`CVAR_NOSETBYACS`) — out of the box nothing persists across a restart despite the wiki's framing, and ACS has no way to detect this; a missing entry and "no database at all" both silently read back as `0`/`""`. `SetDBEntry(ns,key,0)` does **not** delete the row (only `SetDBEntryString(ns,key,"")` does — the int setter always formats a non-empty `"0"` first). `GetDBEntryRank` ranks by strict inequality so ties share a rank, and returns a real `-1` sentinel on a missing key/no-db. `GetDBEntries`/`SortDBEntries` return a plain-`int` result handle into a global vector; `FreeDBResults` only reclaims memory when freed in strict LIFO order, and `CountDBResults` returns `-1` (not `0`) for a bad handle. `GetDBResultKeyString`/`GetDBResultValueString` return the literal strings `"Invalid handle"`/`"Invalid index"` on failure instead of `""` — a real footgun if not checked against `CountDBResults` first — while `GetDBResultValue` degrades silently to `0`. `BeginDBTransaction`/`EndDBTransaction` are **not nestable**; a second `Begin` before an `End` fails at the SQLite level with only a console message, invisible to the script.
- [Inventory family](families/inventory.md) — `ClearInventory`/`ClearActorInventory`/`GiveInventory`/`GiveActorInventory`/`TakeInventory`/`TakeActorInventory`/`CheckInventory`/`CheckActorInventory`/`UseInventory`/`UseActorInventory`/`CheckWeapon`/`SetWeapon`/`GetWeapon`/`DropItem`/`DropInventory`/`GetMaxInventory`, all tier A. `GetWeapon` reads the same `ReadyWeapon` field `CheckWeapon` compares against, but lacks `CheckWeapon`'s Zandronum-only pre-spawn `StartingWeaponName` fallback — the two can disagree right after a player spawns on a server. The Check/Give/Take/Clear core funnels through 4 shared static helpers with a real `tid==0` asymmetry (`CheckActorInventory(0,...)` always returns `0` — neither "activator" nor "all players" like its Give/Take/Clear siblings) and a case-sensitivity crack (`GiveInventory`'s `"Armor"` alias is case-insensitive, `TakeInventory`'s is case-sensitive, and they map to *different* classes). `UseInventory`/`UseActorInventory` and `CheckWeapon`/`SetWeapon` are an unrelated subsystem despite the shared naming: `Use*` actually invokes the item's `Use()` effect (and its no-activator return can be a **sum > 1** across players, not a bool), `CheckWeapon` checks the equipped weapon slot (not possession) with a Zandronum-only starting-weapon fallback, and `SetWeapon` never grants a weapon and has an undocumented ammo-availability gate. `DropItem` spawns a brand-new world item (not from inventory); `DropInventory` genuinely tosses a pickup out of the actor's inventory, unlike `TakeInventory`'s plain destroy. **`GetMaxInventory` (-93) is dead in Zandronum** — no enum member, no switch case, same never-backported ZDoom-93-99 gap already documented for `SpawnParticle` (-96) in the [spawning family](families/spawning.md); the wiki page itself flags the gap and suggests `GetAmmoCapacity` as a workaround.
- [Login/account family](families/login-account.md) — `PlayerIsLoggedIn`/`GetPlayerAccountName`; `GetPlayerAccountName` tier A (wiki-sourced), `PlayerIsLoggedIn` tier B (no wiki page found for it, source-verified only). Both are thin wrappers around the same gate (`NETWORK_GetState()==NETSTATE_SERVER && SERVER_IsValidClient(player)`) and the same `SERVER_GetClient(player)` object. **Server-only in effect** — singleplayer, a listen server's own local view, and `CLIENTSIDE` scripts all fall outside the gate: `PlayerIsLoggedIn` silently returns `false` unconditionally (most non-dedicated-server sessions see `false` for every player, every time) and `GetPlayerAccountName` silently returns `""`, regardless of actual login state. `SERVER_IsValidClient` also fails closed the same way for an out-of-range/not-in-game/bot player, indistinguishable from "not logged in." `GetPlayerAccountName` formats `"n@localhost"` (n = slot) when server-side but not logged in, and has an undocumented gap: it ignores the client's own `WantHideAccount` opt-in that suppresses account-name broadcast over normal netcode, so a script can read the real name anyway. `PlayerIsLoggedIn` has no such gap (reads a plain bool, not the formatted name).
- [Lump I/O](families/lump-io.md) — `LumpOpen`/`LumpRead`/`LumpReadString`/`LumpGetInfo`/`LumpClose` all tier A. **`LumpOpen` refcount guard is broken in Zandronum** — one `LumpClose` per `LumpOpen`, always. `LumpOpen`'s `startIndex` is mandatory here (bcc rejects the 1-arg call the wiki shows) and is exclusive of the index passed. `LumpRead`'s wiki example has swapped args (pos/type). **`LumpReadArray` cannot be called from this toolchain at all** — confirmed by compile test, not just absent from grep — despite being a real, fully-implemented engine feature. `LumpGetInfo`'s `LUMP_INFO_NAMESPACE`/`WAD` and `GetWadInfo` are also real-but-unnamed in `zcommon.bcs` (raw int literals only).
- [Named script execution](families/script-execution.md) — `Acs_NamedExecute`/`Acs_NamedExecuteAlways`/`Acs_NamedExecuteWait`/`Acs_NamedExecuteWithResult`, all tier A. All resolve the script name the same way and share a Zandronum clientside/netcode carve-out, but **the carve-out's fallback return value polarity differs per function** — `Execute`/`ExecuteAlways` return `true` unconditionally when handed off to clients, `ExecuteWithResult` returns `false`/`0`. `ExecuteAlways`'s `map` is mandatory in this toolchain despite being optional at the engine level; `map==0` means current map. `ExecuteWait` is a compiler macro (not an opcode) that discards `Acs_NamedExecute`'s bool result, so an unresolved script name makes the caller hang forever instead of failing cleanly. `ExecuteWithResult` defaults to `1` (not `0`) if the target script never calls `SetResultValue`.
- [Plane-trigger family](families/plane-trigger.md) — `SetFloorTrigger`/`SetCeilingTrigger`, both tier A. Not a mandatory-sequence family — each is independently callable — but both opcodes share one C++ class (`DPlaneWatcher`) almost verbatim, so nearly every finding applies to both identically: arms a per-tic polling thinker (not an instant check) that fires `special(args)` once the tagged sector's floor/ceiling crosses a `height`-derived threshold snapshotted at call time, then self-destructs; **`height == 0` never fires** (permanent, harmless no-op thinker); `tag` has no zero-tag point-in-sector fallback (unlike `GetSectorFloorZ`/`Floor_MoveToValue`) — it watches literal tag-0 sectors, first match only; bad tag is a silent no-op, not a crash; `special`'s activator/line/side are frozen from the calling script, not re-resolved when the watcher fires.
- [Spawning family](families/spawning.md) — `Spawn`/`SpawnForced`/`SpawnSpot`/`SpawnSpotForced`/`SpawnSpotFacing`/`SpawnSpotFacingForced`/`SpawnProjectile`/`SpawnDecal`/`SpawnParticle`, all tier A. The six coordinate/spot variants all funnel through the same `DoSpawn`/`DoSpawnSpot`/`DoSpawnSpotFacing` helpers — "Forced" only skips the `P_TestMobjLocation` placement check, "Spot" resolves position from an existing TID (falls back to the activator at `spottid=0`, spawns once per matching actor, skips Zandronum-only `STFL_HIDDEN_INSTEAD_OF_DESTROYED`-flagged spots — none of this is on the wiki), and "Facing" copies the spot's own angle instead of taking one. `SpawnForced` (119 call sites here) never returns the new actor's tid, only a spawn count. `SpawnProjectile` is direction/speed-based, always void, and its `speed`/`vspeed` args are undocumented-by-the-wiki 1/8-map-unit-per-tic units. `SpawnDecal` doesn't spawn an actor at all — it line-traces and stamps a `DECALDEF` decal, and Zandronum is **missing the wiki's `SDF_FIXED_ZOFF`/`SDF_FIXED_DISTANCE` flags** entirely. `SpawnParticle` is the family's landmine: it compiles fine (`zcommon.bcs` extension function -96) but **Zandronum never implemented ACSF 93-99 at all** — no enum member, no switch case — so every call silently falls through to `default: return 0` and does nothing.
- [ZDoom math functions](families/zdoom-math-stubs.md) — `ZDoom_Floor`/`ZDoom_Round`/`ZDoom_Ceil` (wiki names `Floor`/`Round`/`Ceil`), tier A. All three are declared consecutively in `zcommon.bcs` (-207/-208/-209). **Dead on Zandronum** — its `EACSFunctions` enum jumps from 204 straight past 205-209, so every call falls through to `default: return 0;` and silently always returns `0` regardless of input; use the wiki's own bit-trick fallbacks there. **Real and implemented on UZDoom** — `ACSF_Floor`/`ACSF_Round`/`ACSF_Ceil` at the same 207-209 slots have working `case` bodies, no fallback needed. `Sin`/`Cos`/`Sqrt` are unaffected on either engine (real compiler builtins, different dispatch path). One file instead of three near-duplicate writeups since all three share this one root cause per engine.

## Functions

### Prose (tier A/B)

- [ACS_Execute](functions/acs_execute.md) (action special, index 80) — tier A. Singleton script execution: resumes if suspended, fails if already running (use `ACS_ExecuteAlways` for multiple concurrent copies); returns `true` unconditionally on deferred cross-map calls; Zandronum server-side callsite for CLIENTSIDE scripts returns `true` without actually running.
- [ACS_ExecuteAlways](functions/acs_executealways.md) (action special, index 226) — tier A. Multiple concurrent instances: always spawns a new script copy instead of singleton/resume behavior; scripts not registered in `RunningScripts` so cannot be suspended/terminated or awaited via `NamedScriptWait` (deadlocks forever if attempted); returns `true` unconditionally on deferred cross-map calls; Zandronum server-side carve-out for CLIENTSIDE scripts returns `true` without actually running.
- [ACS_ExecuteWithResult](functions/acs_executewithresult.md) (action special, index 84) — tier A. Returns `int` result (or `1` if unset), truncated if script blocks before `SetResultValue`; always runs current map; clientside returns `0` not `true` (opposite of Execute/ExecuteAlways); takes four arguments vs. three for Execute.
- [ACS_NamedTerminate](functions/acs_namedterminate.md) (extension function → dispatches to action special `LS_ACS_Terminate`) — tier A. Always returns `true`, even when the target map isn't found or the named script isn't currently running (both are silent no-ops) — not a success signal. Cross-map calls defer via `addDefered`/`P_DoDeferedScripts` rather than terminating immediately; `map` is mandatory in the zt-bcc compiler fork's BCS signature despite a defensive C++ fallback.
- [ACS_Suspend](functions/acs_suspend.md) (action special, index 81) — tier A. Always returns `true` unconditionally, even when the target script isn't running or the target map isn't found — **the wiki's "suspend on next run" is false in Zandronum; `SetScriptState` is a no-op if the script isn't currently running**. Cross-map calls defer via `addDefered`; resumable only via non-`ACS_ALWAYS` `ACS_Execute`/`Acs_NamedExecute`; no clientside broadcast unlike `ACS_Execute`.
- [ACS_Terminate](functions/acs_terminate.md) (action special, index 82) — tier A. Numbered-script variant of `ACS_NamedTerminate`; always returns `true` even when the target map/script isn't found (both silent no-ops). Cannot terminate scripts started with `ACS_ExecuteAlways` or ENTER type — they skip insertion into the `RunningScripts` map so `SetScriptState` lookup silently fails. Cross-map calls defer via `addDefered` rather than terminating immediately. Zandronum-specific: no server-side replication, so terminating a `CLIENTSIDE` script server-side doesn't stop the client's instance.
- [ActivatorSound](functions/activatorsound.md) (compiler builtin, `PCD_ACTIVATORSOUND`) — tier A. Activator-null (e.g. `OPEN` scripts) falls back to an unpositioned, unattenuated (`ATTN_NONE`) sound heard everywhere; activator-present path is positioned at the activator with normal attenuation and is silenced entirely if the activator sits in an `SECF_SILENT` sector — neither branch is mentioned by the wiki. Zandronum netcode replicates the sound to clients.
- [ActivatorTID](functions/activatortid.md) (compiler builtin) — tier A. Returns `activator->tid`, but silently returns `0` if `activator == NULL` (e.g. in `OPEN` scripts, which have no activator at all) — indistinguishable from an activator that legitimately has TID `0`; the wiki example only covers the has-activator case.
- [AddBot](functions/addbot.md) (extension function, index -168; **Zandronum**) — tier A. Server-side bot spawning with name/team options; fails (returns `0`) if no free player slot, invalid bot name, unsupported gamemode for teams, `nobotnodes` map flag, or called from a client in network mode. **Crash risk:** the dispatch calls `strlen()` on `FBehavior::StaticLookupString()`'s return with no NULL check (`p_acs.cpp:8559`) — same class as the crash-checklist's "NULL `char*` from a getter measured with no guard" pattern.
- [AmbientSound](functions/ambientsound.md) (compiler builtin, `PCD_AMBIENTSOUND`) — tier A. Always unpositioned/unattenuated (`ATTN_NONE`, `CHAN_AUTO`) and broadcast to every client unconditionally — no activator involved at all, unlike `LocalAmbientSound`; an invalid `sound` string index is a fully silent no-op, and `volume` is never clamped to the wiki's stated 0-127 range.
- [BanFromGame](functions/banfromgame.md) (extension function, index -172; **Zandronum**) — tier A. Server-side player ban with configurable duration and reason. Wiki names the clamping cvar `sv_allowacsbanfunction`, which doesn't exist — the real cvar is `sv_maxacsbanduration`.
- [Ceiling_MoveToValue](functions/ceiling_movetovalue.md) (action special, index 47) — tier A. Ceiling-height absolute-move with `/8`-scaled speed; `tag==0` targets the line's back sector; **crush is hardcoded off** via `crush=-1` (distinct from `Floor_MoveToValue`'s `crush=0` but functionally equivalent — both prevent damage on impact); **the sister function `Ceiling_MoveToValueAndCrush` (index 280) is declared in `zcommon.bcs` but unimplemented in the engine** — same as `SpawnParticle`/`GetMaxInventory`, calls silently do nothing at runtime; the declared 5th argument is dead.
- [ChangeCeiling](functions/changeceiling.md) — tier A. Compiler builtin sharing engine function `DLevelScript::ChangeFlat` with `ChangeFloor` (only the `floorOrCeiling` arg differs); unknown flat name logs+substitutes a default texture (not a no-op), a resolved empty string silently repaints with the "no texture" dummy, a bad string *index* (not a bad name) is a silent no-op before touching any sector, and on a Zandronum server every `SetSectorFlat` sync also re-syncs the paired floor/ceiling flat together.
- [ChangeFloor](functions/changefloor.md) — tier A. Compiler builtin (`PCD_CHANGEFLOOR`); changes every tagged sector's floor texture, falling back through every texture namespace (not just flats) on lookup via `GetTexture`'s own unconditional `TEXMAN_TryAny`, substituting a default texture with a console warning if an unknown name resolves to nothing at all — vs. a resolved empty string, which silently repaints with the "no texture" dummy with no warning, vs. a fully silent no-op if the *string index* itself is invalid. Zandronum syncs the change to clients via `SERVERCOMMANDS_SetSectorFlat`, which also happens to resend the sector's ceiling flat in the same message.
- [ChangeLevel](functions/changelevel.md) — tier A. All six wiki-documented flags verified exact, but `CHANGELEVEL_CHANGESKILL` is dead engine-side (skill change is gated solely by `skill != -1`) and `CHANGELEVEL_HIDENAME` is unreachable from ACS (always masked out, no BCS constant); omitting the optional `skill` argument compiles to a literal `0`, not `-1`, silently resetting to `SKILL_VERY_EASY`.
- [ChangeSkill](functions/changeskill.md) (action special, index 179) — tier A. Queues a skill change for the next map load; validates the skill index against `AllSkills.Size()` and silently aborts on out-of-bounds (sets `NextSkill = -1`).
- [ChangeSky](functions/changesky.md) (compiler builtin, `PCD_CHANGESKY`) — tier A. `sky1`/`sky2` are independently applied only if non-empty — `""` leaves that slot's *previous* sky untouched, not a "clear"/"same as other slot"; names are silently truncated to 8 chars (safe, no overflow); an unresolvable texture name isn't an error, just a console warning + default-texture substitution while the stored name string still updates; Zandronum-only netcode (absent from the wiki) broadcasts the change server→client and correctly catches up late joiners via a MAPINFO diff.
- [ChangeTeamScore](functions/changeteamscore.md) (extension function, index -154) — tier A. Wiki's first param is mislabeled `player` (it's a team index); the shared `SCORE_*` enum has 9 members but only 4 are handled here (others silently no-op); value is clamped non-negative except for `SCORE_FRAGS`; a no-op (value unchanged) returns `0`, indistinguishable from a real failure; `announce` is dropped entirely for `SCORE_DEATHS` and is further conditioned on score-increase / gamemode flags for the rest.
- [CheckActorClass](functions/checkactorclass.md) (extension function, index -27) — tier A. Case-insensitive class-name match against an actor's class type; returns `false` on NULL actor, nonzero-TID miss, or class mismatch (all three silently conflated); only the first actor of a shared-TID group is checked; companion getter [GetActorClass](functions/getactorclass.md) returns the literal string `"None"` instead on the NULL-actor path rather than `false`.
- [CheckActorProperty](functions/checkactorproperty.md) (extension function, index -22) — tier A. Compares an actor property against a value with special string/boolean handling; string properties use case-insensitive comparison; boolean properties normalize the operand (`!!value`) so any nonzero value means "true"; supports the identical 42-property set as `GetActorProperty` (verified switch-for-switch parity); wiki lists 8 additional `APROP_*` constants that don't work here (7 compile but return 0 silently, 1 doesn't compile at all); NULL actor and unknown property both silently return 0; **crash risk**: if you pass a bare `int` instead of a string-table index for a string property, the engine may dereference NULL.
- [CheckActorState](functions/checkactorstate.md) (extension function, index -99) — tier A. Declared in `zcommon.bcs` but **never implemented in Zandronum's engine** — ACSF entries 93–99 were skipped during ZDoom backport development, so calls silently return `0` regardless of input.
- [CheckAutomap](functions/checkautomap.md) (extension function, index -189) — tier B. Local client's automap display state: `0` off, `1` fullscreen (3D view replaced), `2` overlay (3D view still rendering underneath). **Not declared in `zt-bcc`'s `lib/zcommon.bcs` at all** — the engine implements it but the compiler ships no `special` wrapper, so a project must add its own `-189:CheckAutomap():int;` declaration before calling it.
- [CheckClass](functions/checkclass.md) (extension function, index -200) — tier B. **Never implemented in Zandronum's engine** — no `ACSF_CheckClass` case exists anywhere in `p_acs.cpp`, the same never-backported 200–203 range as `SetActorFlag`; every call silently returns `false`. Use `CheckActorClass` (-27) instead, which is real and working.
- [CheckFlag](functions/checkflag.md) (extension function, index -75) — tier A. Checks whether an actor has a named DECORATE flag set; the three false cases (actor not found, unknown flag name, flag genuinely unset) are indistinguishable from the return value alone, and an unknown flag name prints a console error rather than failing to compile. The inverse `SetActorFlag` does not exist in Zandronum — see that doc for the asymmetry.
- [CheckProximity](functions/checkproximity.md) (extension function, index -98) — tier A. Declared in `zcommon.bcs` with all 13 `CPXF_*` flag constants, but **never implemented in Zandronum's engine** — no `case ACSF_CheckProximity` exists, so every call compiles fine and silently returns `0` at runtime. Wiki also disagrees with the compiled signature on the first parameter's type (`int tid` vs. `str`).
- [CheckScript](functions/checkscript.md) (extension function, value 188 in `EACSFunctions`; **Zandronum/Skulltag**) — tier B. Checks whether a named/numbered script exists. Postdates the 3.2.1 target (3.3-alpha only). **Not callable from `zt-bcc`** — engine-real (real dispatch `case`) but no `zcommon.bcs`/`builtin.c` entry at any name for this numeric slot (confirmed by numeric-slot check, unlike `IsMultiplayer`'s alias case).
- [CheckSight](functions/checksight.md) (extension function, index -35) — tier A. Line-of-sight check between one or more source and destination actors/TIDs; `CSF_NOFAKEFLOORS`/`CSF_NOBLOCKALL` flags verified real and remapped internally to engine `SF_*` sight flags; returns true if any source can see any destination.
- [ClassifyActor](functions/classifyactor.md) (compiler builtin) — tier A. Returns a bitfield of actor classification flags (`ACTOR_PLAYER`/`MONSTER`/`MISSILE`/`GENERIC` plus optional `ALIVE`/`DEAD` for players and monsters); when `tid == 0` and there's no activator returns `ACTOR_WORLD` instead of `ACTOR_NONE`; classification categories are mutually exclusive.
- [CloseMenu](functions/closemenu.md) (extension function, index -171) — tier A. The wiki's "0 on error e.g. client not in a menu" is false in Zandronum — `M_ClearMenus()` is a safe no-op on both the server and client (`ServerCommands::CloseMenu::Execute`) paths, so the function always returns 1 as long as the activator has a valid player; "already not in a menu" and "successfully closed" are indistinguishable.
- [ConsoleCommand](functions/consolecommand.md) (compiler builtin) — tier A. The 2 optional trailing ints in the declared signature are dead (never read); the wiki's command denylist is enforced piecemeal, one `ACS_IsCalledFromConsoleCommand()` guard per `CCMD`, not a central blacklist — any new `CCMD` is callable unless its author added the same guard; `UNSAFE_CCMD`-flagged commands aren't blocked by the unsafe-execution-context mechanism when called this way, only by the same per-command guard; `cl_protectcvars` and the CVARINFO/`archivecvar` interaction are both real but narrower than the wiki phrasing implies.
- [ConsolePlayerNumber](functions/consoleplayernumber.md) (extension function, index -102) — tier A. Reads the persistent `consoleplayer` global (`-1` only when `NETWORK_GetState()==NETSTATE_SERVER`), unlike the activator-derived `PlayerNumber()` builtin — which is why it keeps working in `DISCONNECT` scripts where `PlayerNumber()` returns `-1`.
- [Cos](functions/cos.md) (compiler builtin) — tier A. Both argument and return are typed `fixed` in the compiler's own builtin table, contradicting the ZDoom wiki's declared `int angle` signature; `angle` is a fixed-point fraction of a full turn that wraps for free outside `[0.0, 1.0)`; `Cos`/`Sin` share one lookup table with a quarter-turn index offset, not independent computations.
- [DamageThing](functions/damagething.md) (action special, index 73) — tier A. Activator-only (no TID parameter); returns activator existence, not damage success. Zero amount guarantees kill via TELEFRAG_DAMAGE, bypassing all invulnerability; negative amount heals but doesn't replicate to clients.
- [Delay](functions/delay.md) (compiler builtin) — tier A. `Delay(0)`/negative is not a safe no-op — it never sets `SCRIPT_Delayed`, so a runaway loop that computes a zero delay still runaway-terminates; also resumes execution in the *same* tic its counter hits zero, not the next one.
- [Door_Open](functions/door_open.md) (action special, index 11) — tier A. Raises ceiling to four units below surrounding lowest; manual-trigger (tag=0, *usefail on one-sided) vs remote-trigger (tag≠0) behavior differs; returns 0 if ceiling already moving; speed uses the `SPEED()` `/8` macro (pass 16 for normal/64 for fast doors); lighttag lighting effect silently disabled by `COMPATF_NODOORLIGHT`.
- [ExecuteClientScript](functions/executeclientscript.md) (extension function, index -144; `NamedExecuteClientScript` at -145) — tier A. `client` is a plain validated player index; an invalid one silently returns `0` with no console message (unlike the two script-validation failures, which do print one); a demo-playback no-op still returns `1`; the CLIENTSIDE-flag check has a `SCRIPTF_Net`+compat-flag carve-out the wiki doesn't mention.
- [Exit_Normal](functions/exit_normal.md) (action special, index 243) — tier A. Exits to the next map, spawning at the player start whose arg0 matches pos; exit is deferred to next tic and can be blocked by `DF_NO_EXIT`, survival countdown, monster-kill requirements, or death during hub gameplay — return `true` does not guarantee level exit.
- [Exit_Secret](functions/exit_secret.md) (action special, index 244) — tier A. Silent degradation to normal exit if no secret map defined; returns true only if gates pass (NULL activator bypasses all gates); false means gate blocked (activator killed/teleported). Five blocking gates: NULL activator, `DF_NO_EXIT` (kills), survival countdown (kills; checked twice), `DF2_KILL_MONSTERS` coop (teleports), hub-map dead-activator singleplayer only. Zandronum-specific: `DF2_KILL_MONSTERS` and survival countdown both mutate state, not just return values.
- [FadeTo](functions/fadeto.md) (compiler builtin, `PCD_FADETO`) — tier A. Screen-tint fade effect over time for the activator or all players; **activator without a player silently no-ops** (undocumented by ZDoom wiki). Zandronum adds server→client netcode replication. The "decimal literal requirement" is compile-time-graceful but runtime-critical: bcc accepts `FadeTo(255,0,0,1,2)`, but `1`/`2` interpret as fixed `1/65536`, not `1.0`.
- [FixedDiv](functions/fixeddiv.md) (compiler builtin) — tier A. Saturating (not trapping) fixed-point divide: division by zero and near-overflow both silently return `FIXED_MAX`/`FIXED_MIN` instead of erroring, a fact absent from the wiki page and only visible in `m_fixed.h`'s `SafeDivScale16`.
- [FixedMul](functions/fixedmul.md) (compiler builtin) — tier A. Must use this (not `*`) for fixed×fixed multiply, unlike fixed×int; does the multiply in a 64-bit intermediate so it doesn't overflow like a hand-rolled 32-bit `(a*b)>>16` would.
- [Floor_MoveToValue](functions/floor_movetovalue.md) (action special, index 37) — tier A. `speed` is `/8`-scaled fixed point, not literal units/tic; the declared 5th arg (`arg4`) is silently dead in Zandronum's implementation; crush/change are hardcoded off; `tag=0` uses the triggering line's back sector.
- [ForceToSpectate](functions/forcetospectate.md) (extension function, index -106) — tier A. **The wiki's function name doesn't exist in this toolchain** — `zcommon.bcs` exposes this same ACSF index only as `KickFromGame(int,str):bool`, a pre-2016-rename name that never got updated to match the engine's current `ACSF_ForceToSpectate`; call `KickFromGame`, not `ForceToSpectate`. Also: no-ops to `0` in client mode, and the "already spectating" guard respects the same `GMF_DEADSPECTATORS`/`bDeadSpectator` distinction as [PlayerIsSpectator](functions/playerisspectator.md) — a dead spectator isn't "true" and can still be force-spectated. The `reason` string is broadcast server-wide, not shown privately to the target.
- [GameSkill](functions/gameskill.md) (compiler builtin, `PCD_GAMESKILL`) — tier A. Returns the skill definition's `ACSReturn` property (arbitrary int, set via MAPINFO), not the skill index; stock Doom defaults to 0-4 matching the `SKILL_*` enum, but custom MAPINFO can override per-skill.
- [GameType](functions/gametype.md) (compiler builtin) — tier A. `GAME_NET_TEAMGAME=4` is real in the engine but never declared in zt-bcc's `zcommon.bcs`/headers (raw literal `4` needed); the wiki's CTF/Skulltag/Domination/TeamGame-vs-Team DM/LMS/Possession split is correct and traces to cascading `CUSTOM_CVAR` callbacks that force `teamgame` vs `deathmatch`; `GAME_NET_COOPERATIVE` doesn't distinguish Cooperative from Survival/Invasion (a workaround also checking `GetCVar("invasion")`/`GetCVar("survival")` handles it).
- [GetActorAngle](functions/getactorangle.md) (compiler builtin, `PCD_GETACTORANGLE`) — tier A. Returns fixed-point angle (0.0–1.0 fraction of full turn) for an actor by TID; `SingleActorFromTID` means nonzero TID reads only first match (nonzero-TID asymmetry with `SetActorAngle`, which sets all matching actors); silent `0` on bad TID/no activator/genuine East angle; `angle_t` is unsigned so return is always `[0.0, 1.0)`, never negative; no wiki/fork divergence found.
- [GetActorCeilingZ](functions/getactorceilingz.md) (compiler builtin, `PCD_GETACTORCEILINGZ`) — tier A. Returns the lowest ceiling point above an actor as an absolute 3D-floor-aware world coordinate; like `ActivatorTID`/`GetSectorFloorZ`, silently returns `0` on bad TID, no activator, or a legitimate 0-height ceiling.
- [GetActorClass](functions/getactorclass.md) (extension function, index -68) — tier A. Returns the actor's class name as a string; returns the literal string `"None"` (not `""` or an error) when `tid` doesn't match or the activator is NULL — undocumented on the wiki. Reads first-match-only on a shared TID. Companion to [CheckActorClass](functions/checkactorclass.md), which returns `false` instead on the same NULL-actor path.
- [GetActorFloorZ](functions/getactorfloorz.md) (compiler builtin, `PCD_GETACTORFLOORZ`) — tier A. 3D-floor-aware actor floor height; **unlike `GetSectorFloorZ` (not 3D-floor aware), uses a midpoint test to pick which contact surface an actor is standing on**, and omits `FF_SOLID | FF_EXISTS` floors or actors with `IsNoClip2()`. Silent `0` conflation (bad TID / no activator / genuine zero-height floor indistinguishable); freshly-spawned actors' `floorz` may be stale until first movement.
- [GetActorPitch](functions/getactorpitch.md) (compiler builtin, `PCD_GETACTORPITCH`) — tier A. Gets an actor's pitch as a fixed-point angle (negative = up, positive = down); `tid=0` reads the activator, `tid!=0` reads only the first matching actor — asymmetric with `SetActorPitch`, which updates all. No range clamping enforced at getter level; wiki describes renderer-dependent bounds (software ±32-56°, GL ±90°), GL implementation in Zandronum unverified.
- [GetActorProperty](functions/getactorproperty.md) (compiler builtin) — tier A. `property` has a full named `APROP_*` enum in `zcommon.bcs` the tier-C signature doesn't surface; `tid=0` means activator; the `raw` return is actually plain int **or** `fixed_t` **or** a string handle depending on which property, and getting that wrong silently gives a value off by 65536× or a garbage int-as-string; seven wiki-listed `APROP_*` names compile in zt-bcc's `zcommon.bcs` but are unimplemented in the engine switch and always silently return `0`; unknown property and "actor not found" also both silently return `0`.
- [GetActorSectorLocation](functions/getactorsectorlocation.md) (extension function) — tier A. `str`-typed, but only true when `point=false` (returns SECTINFO sector name or `""`); `point=true` instead returns a raw control-point *index* (or `-1`), not a string — feed it into `GetControlPointInfo` rather than reading it as `str`.
- [GetAmmoCapacity](functions/getammocapacity.md) (compiler builtin, `PCD_GETAMMOCAPACITY`) — tier A. Gets max-carry amount of an ammo type on the activator only; returns the held item's `MaxAmount`, or the class's DECORATE default if the activator has never picked one up (unlike setter counterpart [SetAmmoCapacity](functions/setammocapacity.md), which creates the item); silently returns `0` on NULL activator or a class that isn't a direct child of `Ammo`. Wiki's "falls back to Ammo.BackpackMaxAmount" framing is indirect — a backpack pickup mutates `MaxAmount` directly and this getter just observes the result.
- [GetChar](functions/getchar.md) (extension function, index -15) — tier A. Returns the character at a given index in a string as an int; returns `0` if the string handle is invalid, the index is negative, or the index is out of bounds — no wiki/fork divergence found.
- [GetChatMessage](functions/getchatmessage.md) (extension function, index -148; **Zandronum**) — tier A. Zandronum-only; retrieves a previously received public chat message from a player or the server's 5-slot rolling buffer, FIFO order (offset 0=newest..4=oldest, silently clamped outside that range). Private messages (`sayto`/`sayto_idx`) are never stored. Returned string is a pooled ACS string, not a literal — compare with `StrCmp`/`StrIcmp`, not `==`.
- [GetControlPointInfo](functions/getcontrolpointinfo.md) (extension function, index -182) — tier A. Out-of-range `point` silently returns type-appropriate safe defaults instead of erroring; `POINTINFO_OWNER`'s "no owner" sentinel is the C++-only `TEAM_None` (255), unrelated to and easily confused with the BCS-visible `NO_TEAM` (2) constant; `owner`/`disabled` are only ever initialized by `DOMINATION_Init`, which no-ops outside the Domination gametype, so both fields are undefined leftovers on non-Domination maps.
- [GetCurrentGamemode](functions/getcurrentgamemode.md) — tier A. Extension function `-133`, returns the server's current `GAMEMODE_e` as a string with the `GAMEMODE_` prefix stripped (16 possible values, verified 1:1 against `gamemode_enums.h`); never fails. Pairs with `SetCurrentGamemode`.
- [GetCustomPlayerValue](functions/getcustomplayervalue.md) (extension function, index -157; `SetCustomPlayerValue` at -156, `ResetCustomDataToDefault` at -158) — tier A. Return value's real type depends on the custom column's `DATATYPE_*` — `DATATYPE_FLOAT` comes back fixed-point, `DATATYPE_STRING`/`DATATYPE_TEXTURE` come back as string-table handles, none of which the (stub) wiki page mentions; `PLAYER_IsValidPlayer` does not exclude spectators here, unlike `PlayerCount`/`PlayerInGame`.
- [GetEventResult](functions/geteventresult.md) (extension function, index -152) — tier A. Plain global read (`g_lEventResult`), not gated by event type despite the wiki's framing — "always returns 1" only describes the default seed value for every event type except `GAMEEVENT_ACTOR_DAMAGED`/`_PREMOD`; any event's script chain can make it read back something else via a prior `SetResultValue()`. Wiki's third "compatible" type, `GAMEEVENT_ACTOR_ARMORDAMAGED`, doesn't exist under that name in this toolchain — renamed to `GAMEEVENT_ACTOR_DAMAGED_PREMOD` before the 3.2.1 target.
- [GetGamemodeState](functions/getgamemodestate.md) — tier A. Returns `GAMESTATE_*` (`WAITFORPLAYERS`/`COUNTDOWN`/`INPROGRESS`/`INRESULTSEQUENCE`/`UNSPECIFIED`); per-mode meaning varies (Survival/Invasion/Duel/LMS/Possession each map their own state machine, e.g. Invasion's `IS_BOSSFIGHT`/`IS_WAVECOMPLETE` both count as `INPROGRESS`; other modes fall back to a player-count + end-level-delay heuristic with no real countdown state). Wiki spells it `GetGameModeState`; actual name is `GetGamemodeState` (case-insensitive, both work).
- [GetInvasionState](functions/getinvasionstate.md) (compiler builtin, `PCD_GETINVASIONSTATE`) — tier A. Returns the raw `INVASIONSTATE_e` value (`IS_WAITINGFORPLAYERS`..`IS_MISSIONFAILED`, real named constants in `zcommon.bcs`) or `-1` if Invasion isn't the active gametype; matches the wiki with no fork divergence found. Closely related to `GetInvasionWave` — a future `families/invasion.md` could merge the two.
- [GetInvasionWave](functions/getinvasionwave.md) (compiler builtin) — tier A. Returns `-1` only when the game mode isn't Invasion; the wave counter itself is `0` during the pre-first-wave countdown (`IS_WAITINGFORPLAYERS`/`IS_FIRSTCOUNTDOWN`) and only becomes 1-indexed once `INVASION_BeginWave(1)` actually starts combat — not documented on the wiki.
- [GetLevelInfo](functions/getlevelinfo.md) (compiler builtin, `PCD_GETLEVELINFO`) — tier A. `LEVELINFO_PAR_TIME` returns the raw MAPINFO/DEH number in **seconds, not tics** like every other ACS time value — the `TICRATE` multiply happens only when the intermission screen builds its own copy; `LEVELINFO_SUCK_TIME` is likewise raw and unconverted, and its intended unit is **not** minutes as the option name suggests (the fork's only consumer treats it as hours) — left unresolved in the doc rather than guessed. `LEVELINFO_LEVELNUM` is auto-derived from the map lump name (and can be zeroed by a duplicate-levelnum collision), so `0` is not a reliable "unset" sentinel. All 10 wiki-listed `LEVELINFO_*` selectors were checked individually and **all are really implemented** in the fork's switch — the compiles-but-dead-selector trap from [GetActorProperty](functions/getactorproperty.md) does not reproduce here; an unknown selector silently returns `0`.
- [GetMapPosition](functions/getmapposition.md) (extension function, index -151) — tier A. Returns 1-based rotation position (`MAPPOSITION_CURRENT`/`MAPPOSITION_NEXT`) even though the underlying engine helpers are 0-based; `MAPPOSITION_CURRENT` has an undocumented cross-check that silently returns `0` if the running map doesn't match the rotation's recorded current-position entry (e.g. map changed outside normal rotation advancement) — `MAPPOSITION_NEXT` has no equivalent check.
- [GetMapRotationInfo](functions/getmaprotationinfo.md) (extension function, index -150) — tier A. - [TeleportGroup](functions/teleportgroup.md) (action special, `LS_TeleportGroup` index 77) — tier A. Teleports a group of actors while preserving relative positions around source/destination anchor points; returns `0` if destination anchor doesn't exist or no actors were teleported.
- [TeleportOther](functions/teleportother.md) (action special, index 76) — tier A. Teleports actor(s) specified by TID to a destination marker, unlike `Teleport` which targets the activator; destination must be a `TeleportDest` (or subclass) — a plain mapspot with the destination TID silently fails; velocity and angle behavior depends on the fog flag.
- [terminate](functions/terminate.md) (compiler statement, `PCD_TERMINATE`) — tier A. Same grammar production as `restart`/`suspend`; ends the calling script immediately and synchronously. `bcc` unconditionally appends an implicit `PCD_TERMINATE` after every script body, and a bare `return;` inside a script compiles to the identical opcode — `terminate;`/`return;`/falling off the closing brace are three spellings of the same thing. Don't confuse with `ACS_Terminate`/`Acs_NamedTerminate` ([ACS_NamedTerminate](functions/acs_namedterminate.md)), a different mechanism that terminates an arbitrary *other* script by name/number.
- [Thing_Activate](functions/thing_activate.md) (action special, index 130) — tier A. Unconditionally calls the matching actor(s)' `Activate` C++ method; a confirmed no-op on anything but a living monster, an ice corpse, or one of three overriding classes. Full verification in [Activation](concepts/activation.md).
- [Thing_ChangeTid](functions/thing_changetid.md) (action special, index 176) — tier A. Always returns `1`/`true` regardless of whether any actor matched `oldtid` (not a success signal); skips actors already flagged `OF_EuthanizeMe`; on a Zandronum server, a successful retag auto-syncs to clients via `SERVERCOMMANDS_SetThingTID` (fork-only addition, not in upstream ZDoom).
- [Thing_Damage](functions/thing_damage.md) (action special, index 119) — tier A. Negative/zero `amount` silently heals (clamped to `SpawnHealth()`, `mod` ignored, no client sync); special always returns 1 rather than affected-actor count.
- [Thing_Deactivate](functions/thing_deactivate.md) (action special, index 131) — tier A. Full verification in [Activation](concepts/activation.md).
- [Thing_Destroy](functions/thing_destroy.md) (action special, index 133) — tier A. Destroys actors by TID with optional gibbing and sector-tag filtering; armor reduces damage when extreme=0.
- [Thing_Hate](functions/thing_hate.md) (action special, index 177) — tier A. Type 0 uses single-actor mode (no `TIDtoHate`), incompatible with `hatee=0`; types 1–6 use TID-group mode. - [Thing_Remove](functions/thing_remove.md) (action special, index 132) — tier A. Zandronum-specific hide-vs-destroy fork divergence: level-spawned actors in map-reset game modes are hidden (not destroyed) and remain TID-discoverable via `FActorIterator`; always returns `true` regardless of whether anything was removed; live player bodies cannot be removed.
- [Thing_SetConversation](functions/thing_setconversation.md) (action special, index 79) — tier A. Attaches/clears a Strife/USDF dialogue tree for later `Thing_Activate`/USE interaction; `dlg_id=0` explicitly clears; returns `true` even when `tid!=0` matches zero actors (only fails on a bad `dlg_id` lookup); USDF conversations declared with only a class name (no `Actor`/`Id` field) are unreachable by numeric ID. Not previously documented anywhere in this tree.
- [Thing_SetGoal](functions/thing_setgoal.md) (action special, index 229) — tier A. Sets a monster's goal patrol point; the wiki's `dontchasetarget` parameter name is the inverse spelling of the engine's own `chasegoal` — behavior matches (non-zero prefers goal over target, sets `MF5_CHASEGOAL`), only the name reads as opposite. Returns true if any matching actor was found, even if that actor isn't shootable and thus doesn't actually receive the goal. The wiki's `tid`=0 thing-special idiom does **not** work in Zandronum: `FActorIterator` returns NULL for tid 0, so the call silently fails.
- [Thing_SetSpecial](functions/thing_setspecial.md) (action special, index 127) — tier A. Only sets `args[0..2]` (this special's own 5-param signature has no `arg[3]`/`arg[4]` slot — use the separate `SetThingSpecial` compiler builtin for all 5); always returns `true` regardless of outcome; unlike `Thing_ChangeTid`, a special/args change here is never replicated live to already-connected clients — only synced once, to newly-connecting clients, and only for predicted/spectator-allowed `SectorAction` actors.
- [Thing_Stop](functions/thing_stop.md) (action special, index 19) — tier A. Sets actor velocity to zero; `tid=0` targets the activator, non-zero finds all matching TID. Returns 1 if at least one actor was stopped, 0 otherwise. **Wiki claims it also sets acceleration** — the fork's implementation only zeroes velocity, so actors can re-accelerate next tick. Server sends position+velocity sync for non-players, velocity-only for players (player Z velocity notably excluded).
- [ThingCount](functions/thingcount.md) (compiler builtin) — tier A. Counts live, non-hidden actors by spawn type and/or TID; type=0/tid=0 drop their respective filter, dead actors never count. Fork adds spectator/inventory/hidden-actor exclusions not on the ZDoom wiki page.
- [ThingCountName](functions/thingcountname.md) (compiler builtin, `PCD_THINGCOUNTNAME`) — tier A. Counts live actors by class name; tid 0 = ignore tid; excludes dead/held-inventory/hidden/spectator actors, includes DECORATE replacements, silently returns 0 on unknown class name.
- [ThingSound](functions/thingsound.md) (compiler builtin, `PCD_THINGSOUND`) — tier A. Plays a point sound at *every* actor sharing `tid` (not just one) via `FActorIterator`; per-actor skipped in `SECF_SILENT` sectors; no volume clamping; Zandronum-only `bSoundOnClient` client replication not in vanilla ZDoom; functionally superseded by `PlaySound`.
- [ThrustThing](functions/thrustthing.md) (action special, index 72) — tier A. Directional velocity impulse; `nolimit=1` bypasses 30-unit/tic clamping; server-side-only on multiplayer maps; returns success bool.
- [ThrustThingZ](functions/thrustthingz.md) (action special, index 128) — tier A. Force in quarter map-units per tic; direction `0` = up (default), `1` = down; mode `0` = replace Z-velocity, `1` = add to it. Returns `false` when `tid` is 0 and there is no activator. The activator path uses client-side prediction; the TID path is server-only.
- [Timer](functions/timer.md) (compiler builtin, `PCD_TIMER`) — tier A. Returns `level.time`, distinct from `level.maptime`/`level.totaltime`; reset only on a new game or a non-hub level completion — never touched by hub travel, so within a hub it genuinely tracks time-since-game-start as the wiki claims. Zandronum adds server-authoritative sync to clients via `SetMapTime`, absent from the ZDoom wiki.
- [UniqueTid](functions/uniquetid.md) (extension function, index -46) — tier A. `tid=0` picks a random free TID; `limit=0` means unlimited in both modes; a negative `limit` is silently clamped to `0`/unlimited rather than erroring — undocumented on the wiki; returns `0` on failure, which collides with `0`'s meaning as an input; found TIDs are not reserved by the call itself.
- [VectorAngle](functions/vectorangle.md) (compiler builtin) — tier A. Returns fixed-point fraction-of-turn angle of vector (x,y) (atan2 equivalent); bcc types params `fixed` correctly despite the wiki's misleading `int` framing; (0,0)→0; low precision below ~0.0078 map-unit magnitude.
- [VectorLength](functions/vectorlength.md) (extension function) — tier A. Scale-invariant: the `FIXED2DBL` on the inputs and the `FLOAT2FIXED` on the result cancel exactly, so plain ints and fixed-point both work and `VectorLength(3, 4)` really is `5`. The wiki's `int` and `zcommon.bcs`'s `raw` declarations are therefore both defensible, not a divergence. Overflow is reachable (max ~46341 exceeds the fixed-point output range) and wraps rather than saturating. The wiki's "See also: distance" function doesn't exist in Zandronum.
- [Warp](functions/warp.md) (extension function, `ACSF_Warp` index -92) — tier A. Teleports an actor to a reference actor with offsets/angle adjustment; returns `false` if the reference actor doesn't exist or the destination is blocked by geometry (unless `WARPF_NOCHECKPOSITION`). **Wiki lists `heightoffset`/`radiusoffset`/`pitch` parameters that are not implemented in Zandronum** — only 8 args (`tid`, `xofs`, `yofs`, `zofs`, `angle`, `flags`, `success_state`, `exact`) exist.
